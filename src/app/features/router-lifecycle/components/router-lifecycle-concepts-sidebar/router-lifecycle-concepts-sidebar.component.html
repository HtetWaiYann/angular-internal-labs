What is the lifecycle?

Every navigation fires the same ordered sequence of events on Router.events. You can subscribe to that observable and see each phase happen.

Event order

  1. NavigationStart — the URL is requested
  2. RoutesRecognized — a matching route is found
  3. GuardsCheckStart / End — guards run (if any)
  4. ResolveStart / End — resolvers run (if any)
  5. NavigationEnd — the new view is activated

Steps 3 and 4 are skipped when the route doesn't declare guards or resolvers. A blocked guard ends the navigation with NavigationCancel instead of NavigationEnd.

How to subscribe

Inject Router and read router.events. Filter with instanceof or the RxJS filter operator to react to one event type at a time.

Why guards?

Guards decide whether a navigation can proceed. Use them for authentication, feature flags, or unsaved-changes warnings — anything that should block or redirect a navigation before the new view loads.

Guard types

  • canActivate — block entering a route
  • canActivateChild — block entering any child route
  • canDeactivate — block leaving a route
  • canMatch — prevent a route from matching at all

Return values

  • true — allow
  • false — block (emits NavigationCancel)
  • UrlTree — redirect to another URL
  • Observable / Promise — async; navigation waits

Why resolvers?

Resolvers pre-fetch data so a component renders with everything it needs on the very first run — no spinner inside the component.

Trade-off

A slow resolver delays the whole navigation. The user keeps looking at the old view until it finishes. Try the delay picker on the right to see how a 2-second resolver feels.

For very slow or optional data, fetch inside the component and render a skeleton instead.

Reading resolved data

Inject ActivatedRoute and read route.snapshot.data['key'] once, or subscribe to route.data when the same component is reused across navigations.

Why lazy?

Lazy-loaded routes ship their code in a separate JS chunk that's downloaded only when the user first visits the route. Smaller initial bundle, faster first paint.

loadComponent vs loadChildren

  • loadComponent — one standalone component per chunk
  • loadChildren — a whole route array per chunk

Preloading

Use Angular's PreloadAllModules strategy (or a custom one) to download lazy chunks in the background after the app boots, so subsequent navigations feel instant.
