A guard runs before the component activates and decides whether the navigation is allowed. Return true to allow, false to block, or a UrlTree to redirect. The router wraps the whole guard phase in GuardsCheckStart / GuardsCheckEnd.

demo.guard.ts
export const demoGuard: CanActivateFn = (route, state) => {
  // Sync: return true | false | UrlTree
  // Async: return Observable<boolean> | Promise<boolean>
  return true;
};

// Attach to a route:
{ path: 'guarded', canActivate: [demoGuard], loadComponent: ... }

A resolver fetches data before the component loads, so the component renders with data ready on its first run. Resolvers execute after all guards have passed, wrapped in ResolveStart / ResolveEnd.

demo.resolver.ts
export const demoResolver: ResolveFn<DemoData> = (route, state) => {
  return httpClient.get<DemoData>('/api/demo');
};

// Attach to a route:
{ path: 'resolved', resolve: { demoData: demoResolver }, loadComponent: ... }

// Access in the component:
const data = inject(ActivatedRoute).snapshot.data['demoData'];

Lazy routes load their JS code on demand using loadComponent or loadChildren. The first visit triggers a chunk download wrapped in RouteConfigLoadStart / RouteConfigLoadEnd. Subsequent visits use the cached module and fire no extra events.

app.routes.ts
// Single lazy component:
{
  path: 'lazy',
  loadComponent: () =>
    import('./lazy.component').then(m => m.LazyComponent)
}

// Lazy route module (multiple routes in one chunk):
{
  path: 'lazy',
  loadChildren: () =>
    import('./lazy.routes').then(m => m.LAZY_ROUTES)
}
The first visit to /router/lazy downloads the chunk and emits the events below. Visit again and the cached module is reused — reload the page to see another download.
